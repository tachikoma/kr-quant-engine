# 모의 서버 검증 결과 기록 (브로커 1개당 1부 작성)

절차: `docs/mock_trading_verification.md`. 이 파일을 복사해 채운 뒤 PR에 첨부한다.
계좌번호·토큰·키는 가린다. 주문번호는 필요한 만큼만 적는다. 수행하지 않은 항목은 비워 두지 말고
`미수행 + 사유`를 적는다(미수행이 있으면 판정은 PASS가 될 수 없다).

## 2. 주문·취소 왕복 (문서 3장)
명령: `... --mode demo --with-order` (NH는 `LIVE_ORDER_ENABLED=1`)
| 항목 | 결과 | 메모 |
|---|---|---|
| stage2-authorization (목적지 가드) | | 모의 호스트로 판정됐는가 |
| 시장가 매수 → 매도 왕복 `roundtrip` | | |
| 지정가(-25%) 매수 → 취소 | | |
| `cancel_semantics` | PASS / FAIL | |
| `stage2_unresolved` 발생 여부 | 없음 / 있음 | 있으면 앱에서 수동 정리 후 기재 |

### 2-1. 응답 값 기록 (프리플라이트 JSON의 `note`에서 옮겨 적는다)
| 시점 | is_found | order_qty | filled_qty | remaining_qty | is_filled |
|---|---|---|---|---|---|
| 시장가 매수 전량 체결 직후 | | | | | |
| 취소 직후 | | | | | |
| 취소 후 반복 조회 (몇 초 뒤) | | | | | |
| 없는 주문번호 조회 | | | | | |

### 2-2. 코드 가정과의 일치 여부
| 확인 | 기대 | 실제 | 일치 (O/X) |
|---|---|---|---|
| 취소 직후 `remaining_qty` | 0 | | |
| 취소 후 `filled_qty < order_qty` | True | | |
| 취소 후 `is_filled` | False (KIS는 True 가능) | | |
| 없는 주문번호 | `is_found=False` | | |
| 취소 반영 지연 | 5초 이내 | 몇 초: | |
| 전량 체결 직후 | `is_filled=True`, `filled==order_qty>0`, `remaining==0` | | |
| 취소 후 `order_qty` | 제출 수량 그대로 | | |
| 부분체결 취소의 `filled_qty` | 이후 조회에서 감소 없음 | | |
| 반복 조회 | 모순 값 없음 | | |

X가 하나라도 있으면 아래 "이상 징후"에 해당 응답 원문(가린 것)을 붙인다.
