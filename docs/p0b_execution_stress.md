# P0-B: 거래비용·유동성·운용규모 스트레스 검증 (동결 설정 기준)

- 실행 스크립트: `scripts/p0b_execution_stress.py`
- 기준 전략: `strategy_freeze.json` (freeze 2026-07-21, sha256 `4902b181…48b51e7`)
- 기간: 2016-01-05 ~ 2026-09-28 (2,631 거래일), 유니버스 16종, `price` 기준
- 데이터: `data_cache/` 독립 복제본, digest `eb6be25c…7c91119` (실행 전후 동일 확인)
- 엔진: `run_etf_strategy`, `execution_mode="ohlcv_capacity"`, `parameter_stability` 재사용

## 동결 설정 정합성

`configure_frozen_settings()`가 freeze 파일을 로드(해시 검증)하고 런타임 값과 대조한다.
불일치가 있으면 즉시 중단하며, 실험 변수로 의도한 차이만 `intentional_deviations`에 기록한다.

| 항목 | 동결값 | P0-B 기본 적용 | 비고 |
|---|---|---|---|
| `max_asset_pct` | **0.85** | 0.85 | 이전 초안은 0.5 사용 → 수정 |
| `spread_pct` | **0.0002** | 0.0002 | 이전 초안은 0.0005(기본값) 사용 → 수정 |
| `max_positions` / `rebalance_step_days` | 2 / 20 | 2 / 20 | 일치 |
| `slippage` | 0.0005 | 0.0005 | 일치(비용 축에서만 변동) |
| 유니버스·그룹·과세티커·편차 임계·유동성/상장 필터 | — | — | 전부 일치(`config_diffs=[]`) |

동결값은 **환경변수·모듈 속성에 강제 적용**한다(`exit_check_days=0`, trailing/portfolio 0,
target-weight off, band 0.05, trim off, liquidate on, multi-index off, gating split, US proxy QQQ,
MA/slope 120/20, distribution tax 0). 따라서 주변 셸 환경(`ETF_EXIT_CHECK_DAYS=1` 등)이 결과를
바꿀 수 없고, 적용값은 `run_metadata.json`의 `frozen.applied_settings`에 기록된다.

**의도적 변경(실험 변수)만 예외**: 슬리피지(5~50bp), 수수료·세금 배수(1~3x), AUM,
참여율, 리밸런싱/보유종목 인접값. `--cap 0.5` 비교 실행은 `intentional_deviations`에
`max_asset_pct: 0.85 → 0.5`로 기록된다.

## 방법

| 축 | 구현 | 중복 차감 방지 |
|---|---|---|
| 슬리피지 | `run_etf_strategy(slippage=…)` 5/10/20/30/50bp | 별도 파라미터로만 적용 |
| 거래비용 배수 | `etf_shared.BUY/SELL_FEE_PCT`, `ETF_TAXABLE_SELL_TAX_PCT` × 1/2/3 | 슬리피지·스프레드에 배수 미적용 |
| 스프레드 | 동결값 2bp, 주문 참조가격에 포함 | 총비용에 **가산하지 않음**(참고값만) |
| 유동성/규모 | `ohlcv_capacity` (부분체결·1일 이월·취소) | 기존 정책 그대로 |
| 순위 안정성 | `parameter_stability.run_stability` (cap 고정, 리밸런싱×보유종목 9조합) | 동일 엔진·데이터 |

캐시 안전장치: `--start`가 캐시 시작보다 이르면 상장일로 설명되는 경우만 허용,
`ETF_REFRESH_CACHE=1`/`ETF_USE_CACHE=0`/분류캐시 부재/cwd 불일치는 즉시 중단,
로딩·stability 재로딩 전체를 `network_blocked()`로 감싸 fetch를 차단하고,
실행 전후 `data_cache` digest 동일 여부(가격 16종 + index + 분류 캐시 + 분배금 파일)와
필수 16종 로딩(16/16)을 검증한다. 분류 캐시가 비어 있으면 `get_listing_dates`가 KRX 조회로
나갈 수 있으므로, 해당 fetch 함수도 같은 가드로 차단한다.

## 취약점

1. **세금이 비용의 73%**(추정 모델 기준) — 수수료 인하만으로는 비용 민감도 개선이 제한적.
2. **AUM 5천만원 이상 + 낮은 참여율**에서 체결률이 급락하고 최종자산이 -13~-54% 줄어든다.
3. MDD(-51%)는 비용·유동성 조건과 무관 — 스트레스는 수익률만 깎고 낙폭 위험을 줄이지 않는다.
4. 85% 한도는 집중도를 높여 기준 성과는 개선되지만, 중간 AUM에서 유동성 손실이 커진다.

## 검산

- legacy: `equity == cash + market_value`(전 행), `final_cash == 초기자본 + Σcash_flow + Σ분배금`
  (허용오차 `max(1e-6, 규모×1e-12)`; 잔여 현금 상쇄로 인한 float 오차만 허용)
- capacity: `_execution_capacity_scenario`의 `reconciled` + `filled == actual_trade_filled`
- 적용: legacy 32회(cost 9 + capacity 5 + stability 18), capacity 15회 — 85%·50% 두 실행 모두 통과
- 엔진 수정 1건: capacity 현금 검산 허용오차가 절대 1e-6이라 AUM 10억에서 float 오차(3e-6)를
  실패로 오판 → 거래 규모 기준 허용오차로 보정(실제 위반은 계속 실패, `test_execution_outputs` 통과)

## 한계

- OHLCV capacity는 **가정 기반 진단**이며 실제 주문·체결 증거가 아니다(`executable_fill_claim=False`).
  호가 깊이·큐·시장충격은 모형화하지 않는다.
- 비용 2x/3x는 수수료·세금에만 적용했고, 스프레드·슬리피지는 별도 축이다.
- `est_gross_final`은 비용 단순 가산 근사(복리 효과 미반영).
- **IS/OOS**: freeze 기준 in-sample은 2026-07-21까지, `oos_start_date`는 2026-07-22다.
  이 실험은 2016-01-05~2026-09-28로 **대부분 in-sample**이며, OOS 구간은 약 2개월에 불과하다.
  따라서 본 결과는 동일 기간 성과 비교이며 전략 승인·OOS 검증 근거가 아니다.
- PIT·기업행위·분배금 승인 blocker는 그대로 유지된다(`docs/backtest-integrity.md`).
- 16종·`price` 기준만 검증. NAV/total-return·결측/거래정지 구간은 별도 대상이다.
